<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Untrusted archive → staging filesystem | Entry names/sizes/counts and bytes may be malicious. |
| Staging manifest/documents → durable files/state | Invalid or partial data must not replace current usable configuration. |
| Durable state → exported archive | Privacy-sensitive typed/NLP data must not cross the backup boundary. |
| SAF grant → restored/custom documents | Persisted read grants and provider content are untrusted and must remain read-only and balanced. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-10 | Tampering / Elevation | ZipUtils extraction | high | mitigate | Canonical containment before open, reject absolute/parent paths, bounded known entries, and outside-root tests. |
| T-02-11 | Denial of Service | ZipUtils/BackupManager | high | mitigate | Entry-count/per-entry/aggregate byte quotas, streaming, closed resources, and staging cleanup. |
| T-02-12 | Tampering / DoS | BackupManager restore | high | mitigate | Stage → parse → validate → copy accepted docs → map IDs → normalize → one replacement commit last; no broad tree promotion. |
| T-02-13 | Information disclosure | BackupManager export | high | mitigate | Explicit whitelist of language snapshot and referenced custom documents; inspect archive to assert typed/NLP/clipboard data absence. |
| T-02-14 | Tampering | Manifest/profile remap | high | mitigate | Strict schema/version/type/duplicate checks and explicit stable profileId → new sourceUri mapping. |
| T-02-15 | Information disclosure / DoS | SAF grants and custom documents | high | mitigate | Import/removal grant balance is enforced by Plan 02; restore uses app-owned documents, never broad storage access, and never writes/deletes external provider content. |
</threat_model>
