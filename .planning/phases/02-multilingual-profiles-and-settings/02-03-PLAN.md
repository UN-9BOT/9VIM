<threat_model>
Security acceptance policy: **OWASP ASVS Level 1; block on high-severity threats.** Any unresolved high-severity item blocks plan completion.

## Trust Boundaries

| Boundary | Description |
|---|---|
| Compose inputs → LanguageManager | Names, locale strings, order, toggles, and removal requests are user-controlled. |
| SAF picker result/grant → import adapter | URI/provider failures and grant lifecycle must not become partial visible state or leaked access. |
| Archive/manifest input → restore boundary | Plan 04 must strictly validate schema, records, references, and custom documents before UI-visible replacement. |
| ZIP archive → staging filesystem | Plan 04 must enforce canonical containment and count/per-entry/aggregate quotas. |
| Staging → durable snapshot/files | Plan 04 must complete staged validation/copy/remap before one atomic replacement commit. |
| Durable state → exported archive | Plan 04 must exclude typed text and NLP/learning data by explicit whitelist. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-07 | Tampering / DoS | LayoutScreen commands | medium | mitigate | UI sends typed commands to manager; manager revalidates all invariants; dialog commits only on confirmation. |
| T-02-08 | Spoofing | Profile source presentation | low | accept | Local source badges identify embedded versus custom for clarity; no authentication/security identity is claimed. |
| T-02-09 | DoS | Final-enabled and removal controls | high | mitigate | Disable final toggle in UI and enforce the same rejection/atomic fallback in manager tests. |
| T-02-03-SAF | Information disclosure / DoS | Picker grants | high | mitigate | Plan 02 adapter takes read-only persistable access, releases newly acquired grants on rejection, and releases held grants on forget; UI has no direct resolver mutation. |
| T-02-03-INPUT | Tampering / DoS | UI and archive inputs | high | mitigate | Manager revalidates UI commands; Plan 04 strictly validates archive schema, records, references, and documents before replacement. |
| T-02-03-ZIP | Tampering / DoS | Archive extraction | high | mitigate | Plan 04 rejects escaping/duplicate entries and count/per-entry/aggregate quota violations before any restore result reaches this UI. |
| T-02-03-RESTORE | Tampering | Restore transaction | high | mitigate | Plan 04 validates all staged inputs and commits through one `LanguageManager.replaceAll` call last; this UI observes only the committed result. |
| T-02-03-PRIVACY | Information disclosure | Backup export | high | mitigate | Plan 04 allowlists LanguageConfig plus referenced custom documents and asserts typed text, clipboard, frequency, prediction, and NLP data are absent. |
</threat_model>
